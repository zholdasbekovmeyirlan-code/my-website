# Бәрі: техникалық аудит (2026-10-11)

Аудит репозиторийдің `claude/relaxed-hopper-ozk8zg` тармағы бойынша жасалды (PR #1, `main`-ға әлі біріктірілмеген). `FluentPath-deploy/` — бөлек ескі жоба, аудитке кірмейді.

## 1. Жоба қазір қандай

Бір Node сервері және төрт веб-қосымша (PWA, мобильді браузерге арналған):

| Қосымша | Файл | Рөлі |
|---|---|---|
| Бәрі | `bari/index.html` | Клиент: такси, курьер, тамақ, дүкен, дәріхана |
| Бәрі Pro | `bari/pro.html` | Жүргізуші мен курьер |
| Бәрі Бизнес | `bari/partner.html` | Мейрамхана мен дүкен |
| Әкімші | `bari/admin.html` | Растау, шақыру, статистика |

## 2. Стек және архитектура

- **Сервер:** Node.js ≥ 22.13, CommonJS, сыртқы тәуелділік жоқ (`package.json`-да dependencies жоқ, lockfile қажет емес).
  - `lib/db.js`: `node:sqlite` (SQLite, WAL). Схема `CREATE TABLE IF NOT EXISTS` арқылы жасалады, бөлек миграция жүйесі жоқ.
  - `lib/http.js`: өзіміз жазған роутер, статикалық файлдар, CSP.
  - `lib/auth.js`: телефон мен OTP, сессия токені (sha256 хэші сақталады).
  - `lib/orders.js`: тапсырыстың күй машинасы, тапсырысты ұсыну және тағайындау.
  - `lib/pricing.js`: тарифтер мен баға есебі (тек серверде).
  - `lib/realtime.js`: Server-Sent Events.
  - `lib/sms.js`: `demo`, `mobizon`, `smsc`.
  - `routes/api.js`: барлық API.
- **Клиент:** таза JS (build жоқ, TypeScript жоқ), ортақ модульдер `bari/js/*`. HTML жолдар (template) арқылы рендер жасалады, оқиғалар `data-act` арқылы делегацияланады. Аудармалар `i18n.js`-та (kk/ru кілттері).
- **Карта:** Leaflet + OpenStreetMap тайлдары, мекенжай іздеу Nominatim арқылы (клиенттен тікелей). Маршрут сервисі жоқ: қашықтық сатылы сызықпен шамамен есептеледі.
- **Нақты уақыт:** SSE (`/api/events?token=…`).
- **Деплой:** `Dockerfile`, `render.yaml`, `deploy/` (Compose және Caddy).
- **Демо:** `demo/`. Сервер модульдері браузерде sql.js арқылы жұмыс істейді.

## 3. Не жұмыс істейді (сақтау керек)

- OTP арқылы кіру, сессиялар, `INVITE_ONLY` пилот режимі, әкімшілер `ADMIN_PHONES` арқылы беріледі (тек сервер шешеді).
- Такси мен сәлемдеме: баға серверде есептеледі, ұсыныстар жақын маңдағы жүргізушілерге жіберіледі, тағайындау атомарлы (шартты `UPDATE`). Күйлер: searching → accepted → arrived → riding → done.
- Жеткізу: new → cooking → ready → delivering → done. Тапсырыс кезіндегі баға сақталады (`items_json`), қор (stock) азаяды, бас тартқанда қайта қалпына келеді.
- Мейрамхана панелі (мәзір, тапсырыс), әкімші (растау, шақыру, мекемені иесіне беру), әлеуметтік тариф (әкімші растайды).
- Тапсырыс күйлерінің журналы (`order_events`), уақыт шектеулері (15 мин), офлайн жұмысшыларды тазалау.
- kk/ru тілдері, KZ телефон нөмірін тексеру, тенге (бүтін сан).
- Тесттер: `server/test/*.test.js`, 4 интеграциялық тест.

## 4. Негізгі кемшіліктер мен қателер

**Қателер (түзету оңай):**
1. ✅ *(түзетілді)* **Қайталанған тапсырыс.** Желі үзілсе, клиент «Тапсырыс беру» батырмасын қайта басады. Сонда бірдей жеткізу тапсырысы екі рет жасалады (бір уақытта 3 тапсырысқа дейін рұқсат), қор да екі рет азаяды. Idempotency жоқ.
2. **«Бүгін» уақыт белдеуіне тәуелді.** `setHours(0,0,0,0)` сервердің уақыт белдеуін алады (Render-де UTC). Сондықтан Алматы уақытымен 00:00–05:00 аралығындағы табыс пен сатылым алдыңғы күнге есептеледі (`orders.js:364`, `api.js:335,344`).
3. **Ескірген орын көрсетіледі.** Клиент жүргізушінің соңғы орнын уақытын тексермей көрсетеді (`loc_at` жіберілмейді). Қосымша жабылса, машина бір орында «тұрып» қалады.
4. **Бір қала қатты кодталған.** Алматы шекаралары `validate.js:29` файлында, ал клиент `data.js`-та. Қызмет аймақтарын баптау мүмкін емес.

**Жоқ функциялар:**
- Нативті Android және iOS қосымшалары жоқ (тек PWA, service worker жоқ, офлайн режим жоқ).
- Төлем жоқ (тек қолма-қол), төлем абстракциясы мен webhook жоқ.
- Push-хабарламалар жоқ (SSE тек қосымша ашық тұрғанда жұмыс істейді).
- Маршрут сервисі жоқ, геокодинг клиенттен тікелей Nominatim-ге барады, провайдер интерфейсі жоқ.
- Жүргізуші ұсыныстан бас тарта алмайды, жеке ұсыныс уақыты шектелмейді (бәріне таратылады, бірінші қабылдаған алады).
- Шағым мен қолдау (support tickets), жеткізуді растау (proof of delivery), аккаунтты жою жоқ.
- Әкімші әрекеттерінің аудит журналы жоқ. Рөлдер тек `is_admin` (support рөлі жоқ).
- Клиентке арналған тест жоқ, CI жоқ, линтер конфигі жоқ.

## 5. Қауіпсіздік тәуекелдері

| Тәуекел | Ауырлығы | Қазіргі жағдай |
|---|---|---|
| `SMS_MODE=demo` болса, кез келген адам кез келген нөмірмен кіре алады | Жоғары | `INVITE_ONLY=1` арқылы азайтылған, әкімші панелінде ескерту бар |
| `OTP_SECRET` әдепкі мәні | Орташа | `render.yaml` оны генерациялайды, сервер іске қосылғанда журналға ескерту жазады |
| `X-Forwarded-For`-ға тексерусіз сену (rate limit-ті айналып өтуге болады) | Орташа | Прокси артында ғана қауіпсіз |
| SSE токені URL-да (прокси журналдарына түсуі мүмкін) | Төмен–орташа | EventSource header жібере алмайды, қысқа мерзімді билет керек |
| Rate limit тек кіруде бар | Орташа | Тапсырыс API-ларында шектеу жоқ |
| `innerHTML` шаблондары | Орташа | Барлық мән `B.esc` арқылы өтеді, emoji серверде тексеріледі. Әр жаңа шаблонда сақ болу керек |
| Аккаунтты жою және дербес деректерге қол жеткізу процесі жоқ | Заң талабы | Заңгермен тексеру керек |

## 6. Техникалық қарыз

- Миграция жүйесі жоқ: схема тек `IF NOT EXISTS`, бағанды өзгерту мүмкін емес.
- Демо сервердің роутинг логикасын көшіреді (`demo/backend.js` ішіндегі `handle`). Ортақ модульге шығару керек.
- Типтер жоқ (JSDoc немесе TypeScript), API келісімшарты құжатталмаған.
- SQLite бір инстанс: пилотқа жеткілікті, ал масштаб үшін PostgreSQL керек.

## 7. Басымдық бойынша бес жақсарту

1. ✅ **Тапсырыс құруда idempotency** (`Idempotency-Key`). Қайталанған тапсырыс пен қордың қос азаюын болдырмайды. *Жасалды:* `server/lib/idempotency.js`, клиент әр тапсырысқа бір кілт береді және желі үзілсе бір рет қайталайды. Тесттер: `server/test/idempotency.test.js`, сонымен қатар браузерде жоғалған жауап тексерілді.
2. **Уақыт белдеуі (Asia/Almaty) және ескірген орын.** «Бүгінгі» есептерді дұрыстау, орын жасы 2 минуттан асса жасыру.
3. **Қызмет аймақтарын баптауға болатын ету** (қалалар мен шекаралар конфигте). Аймақтан тыс мекенжайға түсінікті хабар.
4. **Диспетчерді жақсарту:** жүргізуші ұсыныстан бас тарта алады, ұсыныс мерзімі шектеледі, әкімші әрекеттерінің аудит журналы жазылады, API-да rate limit болады.
5. **Төлем абстракциясы мен push-хабарламалар**, содан кейін Capacitor арқылы Android/iOS қаптамасы (қазіргі кодты қайта қолдану).
